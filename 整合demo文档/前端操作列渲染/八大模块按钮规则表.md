# 八大模块按钮规则表

## 一、概述

本文档整理了八大模块在不同状态与不同角色下的按钮显示规则。八大模块为:**论文、教材软著、专利软著、讲座报告、奖励、横向项目、纵向项目、成果转化**。所有按钮规则统一由 `PageRenderServiceImpl` 中的通用规则引擎 `buildCommonActions()` 方法生成,通过模块注册表区分各模块配置。

## 二、通用按钮规则定义

### 2.1 通用按钮规则(适用于全部八大模块)

所有模块共用同一套按钮规则,由 `buildCommonActions()` 方法基于状态编码后缀自动判断按钮显示规则:

| 序号 | 状态条件 | 角色条件 | 权限条件 | 动作Key | 动作文案 | 颜色 | 展示方式 | 排序 |
|------|---------|---------|---------|---------|---------|------|---------|------|
| 1 | 任意状态 | 任意 | 有查看权限 | view | 查看 | default | button | 1 |
| 2 | 审批中或已通过 | 任意 | 有查看权限 | viewProcess | 查看流程 | info | button | 2 |
| 3 | 草稿或驳回 | 记录创建者 | 有编辑权限 | edit | 编辑 | primary | button | 3 |
| 4 | 草稿 | 记录创建者 | 有删除权限 | remove | 删除 | danger | link | 4 |
| 5 | 草稿 | 记录创建者 | 有编辑权限 | submit | 提交 | primary | button | 5 |
| 6 | 驳回 | 记录创建者 | 有编辑权限 | submit | 重新提交 | primary | button | 5 |
| 7 | 审批中 | 当前审批节点处理人 | 有审批权限 | approve | 通过 | success | button | 6 |
| 8 | 审批中 | 当前审批节点处理人 | 有审批权限 | reject | 驳回 | danger | button | 7 |
| 9 | 教研室审批中（`*_JYS_AUDIT`） | 记录创建者（作者） | - | recall | 撤回 | warning | button | 8 |

| 11 | 审批通过（`*_PASSED`） | 科研处审批人 | 有 `{prefix}:kyrevoke` 权限 | recall | 撤回 | warning | button | 8 |

### 2.2 规则说明

- **角色条件说明**：
  - `记录创建者`：当前登录用户ID等于记录的创建者ID（`isOwner()`）
  - `当前审批节点处理人`：当前用户具有该节点审批权限且记录处于对应审批状态
  - `教研室审批人`：当前用户具有教研室审批角色（如 `jys` 角色）
  - `科研处审批人`：当前用户具有科研处审批角色（如 `ky` 角色）

- **状态条件说明**：
  - `草稿`：状态为 `*_DRAFT`
  - `驳回`：状态为 `*_REJECTED*`
  - `审批中`：状态为 `*_AUDIT`
  - `已通过`：状态为 `*_PASSED`

- **权限条件说明**：
  - `有查看权限`：当前用户拥有模块查看权限（如 `system:paper:detail`）
  - `有编辑权限`：当前用户拥有模块编辑权限（如 `system:paper:edit`）
  - `有删除权限`：当前用户拥有模块删除权限（如 `system:paper:remove`）
  - `有审批权限`：当前用户拥有模块审批权限（如 `system:paper:approve`）

## 十一、后端接入实现指引

### 11.1 通用规则引擎原理

`PageRenderServiceImpl` 中已实现通用规则引擎，无需为每个模块单独编写 `buildXxxActions()` 方法。所有模块共用同一套按钮构造逻辑，仅通过 `ModuleConfig` 注册表区分模块编码、流程编码和权限前缀。

### 11.2 接入步骤

1. 在 `PageRenderServiceImpl` 的 `registerModuleConfigs()` 方法中注册模块配置
2. 在 ServiceImpl 中添加 `fillPageRenderData()` 方法，设置 `moduleCode`、`permPrefix`、`processCode`
3. 在列表查询和详情查询方法中调用 `fillPageRenderData()`
4. 如有旧状态码，添加 `mapStateToStatusCode()` 方法兼容映射

### 11.3 规则优先级

按钮规则的生成优先级为：
1. **状态匹配优先**：首先根据状态编码后缀（`_DRAFT`/`_JYS_AUDIT`/`_KYC_AUDIT`/`_PASSED`/`_REJECTED`）确定按钮集合
2. **角色过滤其次**：再根据当前用户角色（创建者/教研室审批人/科研处审批人）过滤动作
3. **权限校验最后**：最后根据权限（如 `{prefix}:revoke`、`{prefix}:kyrevoke`）过滤最终展示的按钮

### 11.4 模块配置注册示例

```java
// 在 registerModuleConfigs() 方法中注册
MODULE_REGISTRY.put("TEXTBOOK", new ModuleConfig(
    "TEXTBOOK",                    // 模块编码
    "system:textbook",             // 权限前缀
    "textbook_approval",           // 流程编码
    "教材软著"                     // 模块名称
));
```

### 11.5 模块接入示例（教材软著）

```java
// ServiceImpl 中 fillPageRenderData() 方法
private void fillPageRenderData(SciJiaocairuanzhu jiaocairuanzhu) {
    if (jiaocairuanzhu == null) return;
    
    SysUser currentUser = ShiroUtils.getSysUser();
    List<String> permissions = buildCurrentPermissions(currentUser);
    List<String> roleKeys = buildCurrentRoleKeys(currentUser);
    String normalizedState = mapStateToStatusCode(jiaocairuanzhu.getState());
    
    PageRenderContext context = new PageRenderContext();
    context.setModuleCode("TEXTBOOK");
    context.setBusinessId(jiaocairuanzhu.getId());
    context.setCurrentState(normalizedState);
    context.setCreatorId(jiaocairuanzhu.getUserId());
    context.setCurrentUser(currentUser);
    context.setPermissions(permissions);
    context.setRoleKeys(roleKeys);
    
    PageRenderStatusMeta statusMeta = pageRenderService.buildStatusMeta(context);
    List<PageRenderActionItem> actions = pageRenderService.buildActions(context);
    
    jiaocairuanzhu.setStatusMeta(statusMeta);
    jiaocairuanzhu.setActions(actions);
}
```
