# 八大模块接入清单

## 一、概述

本文档列出八大模块各自需要改造的 service、controller、list 页面、detail 页面、动作规则来源，形成统一的接入实施清单。八大模块为：**论文、教材软著、专利软著、讲座报告、奖励、横向项目、纵向项目、成果转化**。按照此清单逐项改造，即可完成各模块的页面渲染统一化接入。

---

## 二、后端接入方式（通用规则引擎）

新方案采用**通用规则引擎**，无需为每个模块单独编写状态加载方法和按钮规则方法。所有模块共用同一套按钮构造逻辑，仅通过 `ModuleConfig` 注册表区分模块编码、流程编码和权限前缀。

### 2.1 接入原理

`PageRenderServiceImpl` 中已实现通用按钮规则引擎，核心机制：

1. **模块注册表**：`MODULE_REGISTRY` Map 中已预注册八大模块的模块编码、权限前缀、流程编码
2. **状态映射加载**：`loadAllModuleConfigs()` 启动时自动加载所有已注册模块的状态映射和节点映射
3. **通用按钮规则**：`buildCommonActions()` 基于状态编码后缀（`_DRAFT`/`_JYS_AUDIT`/`_KYC_AUDIT`/`_PASSED`/`_REJECTED`）自动判断按钮显示规则
4. **模块特有按钮**：`addModuleSpecificActions()` 处理模块特有按钮（如横向课题的"提交结项申请"）

### 2.2 状态编码命名规范

所有模块的状态编码必须遵循统一后缀规则：

| 后缀 | 通用语义 | 颜色类型 | 示例状态编码 |
|------|---------|---------|-------------|
| `_DRAFT` | 草稿/待提交 | default（灰色） | REWARD_DRAFT, TEXTBOOK_DRAFT |
| `_JYS_AUDIT` | 教研室审批中 | warning（橙色） | REWARD_JYS_AUDIT, TEXTBOOK_JYS_AUDIT |
| `_KYC_AUDIT` | 科研处审批中 | info（青色） | REWARD_KYC_AUDIT, TEXTBOOK_KYC_AUDIT |
| `_PASSED` | 审批通过 | success（绿色） | REWARD_PASSED, TEXTBOOK_PASSED |
| `_REJECTED` | 审批驳回 | danger（红色） | REWARD_REJECTED, TEXTBOOK_REJECTED |

### 2.4 旧状态码兼容

部分模块（教材软著、专利软著、成果转化）历史数据使用数字状态码，需要在 ServiceImpl 中添加 `mapStateToStatusCode()` 映射方法：

```java
/**
 * 将旧状态码（数字）映射为统一状态编码
 * 示例：教材软著模块旧状态码（0-7）映射为 TEXTBOOK_* 格式
 */
private String mapStateToStatusCode(String state) {
    if (state == null) return "TEXTBOOK_DRAFT";
    // 如果已经是新格式状态编码，直接返回
    if (state.contains("_")) return state;
    // 旧数字状态码映射
    switch (state) {
        case "0": return "TEXTBOOK_DRAFT";
        case "1": return "TEXTBOOK_JYS_AUDIT";
        case "2": case "4": return "TEXTBOOK_KYC_AUDIT";
        case "3": case "5": case "7": return "TEXTBOOK_REJECTED";
        case "6": return "TEXTBOOK_PASSED";
        default: return "TEXTBOOK_DRAFT";
    }
}
```

### 2.5 通用按钮规则

八大模块共用同一套按钮规则，由 `buildCommonActions()` 方法实现：

| 状态语义 | 按钮 | 显示条件 |
|---------|------|---------|
| 草稿（`_DRAFT`） | 查看、编辑、删除、提交 | 创建人/管理员 + 对应权限 |
| 驳回（`_REJECTED`） | 查看、编辑 | 创建人/管理员 + 对应权限 |
| 教研室审批（`_JYS_AUDIT`） | 查看、查看流程、批阅、通过、驳回 | 有 `{prefix}:process` 权限 |
| 教研室审批（`_JYS_AUDIT`） | ~~撤回~~ | **不显示** |
| 科研处审批（`_KYC_AUDIT`） | 查看、查看流程、批阅、通过、驳回 | 有 `{prefix}:process` 权限 |
| 科研处审批（`_KYC_AUDIT`） | 撤回 | 有 `{prefix}:revoke` 权限 |
| 通过（`_PASSED`） | 查看、查看流程 | 有 `{prefix}:info` 权限 |
| 通过（`_PASSED`） | 撤回（管理员） | 有 `{prefix}:kyrevoke` 权限 |

## 三、整体接入流程

### 3.1 后端接入步骤（每个模块通用）

| 步骤 | 改造内容 | 说明 |
|------|---------|------|
| 1 | 领域类添加 `statusMeta` 和 `actions` 字段 | 参照 `SciPaperA.java` 的字段定义 |
| 2 | ServiceImpl 添加 `fillPageRenderData()` 方法 | 设置 moduleCode、permPrefix、processCode，调用公共服务 |
| 3 | ServiceImpl 列表查询方法中调用 `fillPageRenderData()` | 在返回每条记录前调用填充方法 |
| 4 | ServiceImpl 详情查询方法中调用 `fillPageRenderData()` | 在返回详情前调用填充方法 |
| 5 | 旧状态码兼容（如需要） | 添加 `mapStateToStatusCode()` 方法 |

> **注意**：无需修改 `PageRenderServiceImpl`，通用规则引擎已自动支持所有已注册模块。

### 3.2 前端接入步骤（每个模块通用）

| 步骤 | 改造内容 | 说明 |
|------|---------|------|
| 1 | HTML 页面引入 `page-render.js` | 在页面 `<script>` 区域添加引入 |
| 2 | 改造列表页状态列渲染 | 使用 `PageRender.renderStatusToString(row.statusMeta)` |
| 3 | 改造列表页操作列渲染 | 使用 `PageRender.renderActionsToString(actions)` |
| 4 | 注册动作处理器 | 调用 `PageRender.registerHandlers()` 注册所需动作 |
| 5 | 改造详情页底部按钮 | 使用 `PageRender.renderActions()` |
| 6 | 保留原有表单提交逻辑 | 不改动原审批业务逻辑 |

| 验证项 | 验证内容 | 通过标准 |
|--------|---------|---------|
| 列表页状态列 | 各状态在列表页的颜色和文案是否正确 | 与状态映射表一致 |
| 列表页操作列 | 各状态下按钮显示是否正确 | 与按钮规则表一致 |
| 详情页按钮 | 详情页底部按钮显示是否正确 | 与列表页操作列一致 |
| 角色差异 | 不同角色看到的按钮是否正确 | 与按钮规则表一致 |
| 驳回后重新提交 | 驳回状态下编辑后重新提交是否正常 | submit 按钮正确触发 |
| 撤回场景 | 各撤回场景按钮是否正确 | 与按钮规则表一致 |
| 颜色风格 | 状态颜色和按钮颜色是否与现有页面风格一致 | 无明显风格割裂 |
| 原审批流程 | 原有审批提交流程是否正常 | 不受改造影响 |
