# 八大模块接入清单

## 一、概述

本文档列出八大模块各自需要改造的 service、controller、list 页面、detail 页面、动作规则来源，形成统一的接入实施清单。八大模块为：**论文、教材软著、专利软著、讲座报告、奖励、横向项目、纵向项目、成果转化**。按照此清单逐项改造，即可完成各模块的页面渲染统一化接入。

---

## 二、状态配置（第一步）

接入各模块前，需要先配置该模块的状态信息。提供两种方式：**数据库动态加载**（推荐）和**状态编码硬编码**。

### 2.1 方式一：数据库动态加载（推荐）

在 `PageRenderServiceImpl` 中为模块加载状态映射，支持通过数据库配置动态调整状态展示信息。

#### 2.1.1 在 PageRenderServiceImpl 中添加状态映射字段

```java
/** 奖励模块状态映射配置（从数据库动态加载） */
private final Map<String, StatusMapping> rewardStatusMapping = new HashMap<>();

/** 奖励模块审批节点配置（从数据库动态加载） */
private final Map<String, SysApprovalNode> rewardNodeMapping = new HashMap<>();

/** 奖励模块流程编码 */
private static final String REWARD_PROCESS_CODE = "REWARD";
```

#### 2.1.2 在 init() 方法中加载配置

```java
@PostConstruct
public void init() {
    try {
        log.info("开始加载审批流程配置...");
        loadStatusMapping();        // 论文模块
        loadNodeMapping();          // 论文模块
        loadRewardStatusMapping();  // 奖励模块
        loadRewardNodeMapping();    // 奖励模块
        // ... 其他模块的加载方法
        log.info("审批流程配置加载完成");
    } catch (Exception e) {
        log.error("加载审批流程配置失败", e);
    }
}
```

#### 2.1.3 编写模块专属的加载方法

```java
/**
 * 从数据库加载奖励模块状态映射配置
 */
private void loadRewardStatusMapping() {
    rewardStatusMapping.clear();
    
    List<SysApprovalState> states = approvalStateMapper
        .selectSysApprovalStateByProcessCode(REWARD_PROCESS_CODE);
    if (states == null || states.isEmpty()) {
        log.warn("未找到流程 {} 的状态配置", REWARD_PROCESS_CODE);
        return;
    }
    
    for (SysApprovalState state : states) {
        if ("0".equals(state.getStatus())) {
            String colorType = getColorTypeBySort(state.getSort());
            rewardStatusMapping.put(state.getStateCode(), 
                new StatusMapping(state.getStateName(), colorType, 
                    getSemanticByStateCode(state.getStateCode())));
        }
    }
}

/**
 * 从数据库加载奖励模块审批节点配置
 */
private void loadRewardNodeMapping() {
    rewardNodeMapping.clear();
    
    SysApprovalProcess process = approvalProcessMapper
        .selectSysApprovalProcessByProcessCode(REWARD_PROCESS_CODE);
    if (process == null) {
        log.warn("未找到流程编码 {} 的配置", REWARD_PROCESS_CODE);
        return;
    }
    
    List<SysApprovalNode> nodes = approvalNodeMapper
        .selectSysApprovalNodeByProcessId(process.getId());
    if (nodes == null || nodes.isEmpty()) {
        log.warn("未找到流程 {} 的节点配置", REWARD_PROCESS_CODE);
        return;
    }
    
    for (SysApprovalNode node : nodes) {
        if ("0".equals(node.getStatus())) {
            rewardNodeMapping.put(node.getNodeCode(), node);
        }
    }
}
```

#### 2.1.4 在 getStatusMapping() 中注册模块

```java
private Map<String, StatusMapping> getStatusMapping(String moduleCode) {
    if ("PAPER".equals(moduleCode)) {
        return paperStatusMapping;
    }
    if ("REWARD".equals(moduleCode)) {
        return rewardStatusMapping;
    }
    if ("TEXTBOOK".equals(moduleCode)) {
        return textbookStatusMapping;
    }
    if ("PATENT".equals(moduleCode)) {
        return patentStatusMapping;
    }
    if ("LECTURE".equals(moduleCode)) {
        return lectureStatusMapping;
    }
    if ("HORIZONTAL_APPLY".equals(moduleCode) || "HORIZONTAL_OVER".equals(moduleCode)) {
        return horizontalStatusMapping;
    }
    if ("VERTICAL_APPLY".equals(moduleCode) || "VERTICAL_OVER".equals(moduleCode)) {
        return verticalStatusMapping;
    }
    if ("TEC_TRA".equals(moduleCode)) {
        return tecTraStatusMapping;
    }
    // 未识别的模块返回空映射
    return Collections.emptyMap();
}
```

### 2.2 方式二：状态编码硬编码

如果数据库中尚未配置状态信息，可以通过状态编码后缀自动识别通用语义。

#### 2.2.1 状态编码命名规范

所有模块的状态编码必须遵循统一后缀规则：

| 后缀 | 通用语义 | 颜色类型 | 示例状态编码 |
|------|---------|---------|-------------|
| `_DRAFT` | 草稿/待提交 | default（灰色） | REWARD_DRAFT, TEXTBOOK_DRAFT |
| `_JYS_AUDIT` | 教研室审批中 | warning（橙色） | REWARD_JYS_AUDIT, PATENT_JYS_AUDIT |
| `_KYC_AUDIT` | 科研处审批中 | info（青色） | REWARD_KYC_AUDIT, LECTURE_KYC_AUDIT |
| `_PASSED` | 审批通过 | success（绿色） | REWARD_PASSED, HORIZONTAL_APPLY_PASSED |
| `_REJECTED` | 审批驳回 | danger（红色） | REWARD_REJECTED, VERTICAL_OVER_REJECTED |

#### 2.2.2 通用语义自动识别

`PageRenderServiceImpl` 中的 `getSemanticByStateCode()` 方法已实现通用识别：

```java
private String getSemanticByStateCode(String stateCode) {
    if (stateCode == null) return "未知";
    if (stateCode.endsWith("_DRAFT")) return "待提交";
    if (stateCode.endsWith("_AUDIT")) return "审批中";
    if (stateCode.endsWith("_PASSED")) return "通过";
    if (stateCode.endsWith("_REJECTED")) return "驳回";
    return "未知";
}
```

#### 2.2.3 颜色类型自动映射

前端 `page-render.js` 中已实现关键词匹配：

```javascript
function getStatusColor(statusCode) {
    if (!statusCode) return '#6c757d';
    if (statusCode.includes('DRAFT')) return '#6c757d';      // 灰色
    if (statusCode.includes('JYS_AUDIT')) return '#f59e0b';  // 橙色
    if (statusCode.includes('KYC_AUDIT')) return '#0ea5e9';  // 青色
    if (statusCode.includes('PASSED')) return '#22c55e';     // 绿色
    if (statusCode.includes('REJECTED')) return '#ef4444';   // 红色
    return '#6c757d';
}
```

#### 2.2.4 适用场景

- **临时调试**：数据库配置未完成时，可通过状态编码快速验证
- **兜底逻辑**：数据库查询失败时，系统自动降级使用编码后缀识别
- **推荐做法**：生产环境仍应使用数据库动态加载方式

### 2.3 旧状态码兼容

部分模块（教材软著、专利软著、成果转化）历史数据使用数字状态码，需要在 ServiceImpl 中添加映射方法：

```java
/**
 * 教材软著旧状态码（0-7）映射为统一状态编码
 */
private String mapStateToStatusCode(String state) {
    if (state == null) return "TEXTBOOK_DRAFT";
    
    // 如果已经是新格式状态编码，直接返回
    if (state.contains("_")) return state;
    
    // 旧数字状态码映射
    switch (state) {
        case "0": return "TEXTBOOK_DRAFT";
        case "1": return "TEXTBOOK_JYS_AUDIT";
        case "2": 
        case "4": return "TEXTBOOK_KYC_AUDIT";
        case "3": 
        case "5": 
        case "7": return "TEXTBOOK_REJECTED";
        case "6": return "TEXTBOOK_PASSED";
        default: return "TEXTBOOK_DRAFT";
    }
}
```

## 三、整体接入流程

### 3.1 后端接入步骤（每个模块通用）

| 步骤 | 改造内容 | 说明 |
|------|---------|------|
| 1 | 状态配置（见第二章） | 数据库动态加载或状态编码硬编码 |
| 2 | 领域类添加 `statusMeta` 和 `actions` 字段 | 参照 `SciPaperA.java` 的字段定义 |
| 3 | ServiceImpl 列表查询方法中补充 `fillPageRenderData()` | 在返回每条记录前调用填充方法 |
| 4 | ServiceImpl 详情查询方法中补充 `fillPageRenderData()` | 在返回详情前调用填充方法 |
| 5 | PageRenderServiceImpl 中添加 `buildXxxActions()` 方法 | 实现该模块的按钮规则逻辑 |
| 6 | PageRenderServiceImpl 中 buildActions() 添加模块 case | 在 switch 分支中调用对应的按钮方法 |

### 3.2 前端接入步骤（每个模块通用）

| 步骤 | 改造内容 | 说明 |
|------|---------|------|
| 1 | HTML 页面引入 `page-render.js` | 在页面 `<script>` 区域添加引入 |
| 2 | 改造列表页状态列渲染 | 使用 `PageRender.renderStatusToString(row.statusMeta)` |
| 3 | 改造列表页操作列渲染 | 使用 `PageRender.renderActionsToString(actions)` |
| 4 | 注册动作处理器 | 调用 `PageRender.registerHandlers()` 注册所需动作 |
| 5 | 改造详情页底部按钮 | 使用 `PageRender.renderActions()` |
| 6 | 保留原有表单提交逻辑 | 不改动原审批业务逻辑 |
